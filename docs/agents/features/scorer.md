# Scorer (replaces wknd-stats live tracking)

Phase 1 (2026-10-25): one device scores a league game (both teams, lineups off), offline-first; an admin publishes it from the game's Scoring tab. Live score for everyone (site + app) added 2026-10-25. Later phases (video re-track, two scorers, lineups mode, Papawis) are planned, not built. Product decisions live in the scorer memory notes; mockups: claude.ai/artifact/6HBcExzSGjoQSzvjpkMPJQ.

## Files
- `public/score-engine.js` — the rules and maths, shared by the phone and the server (plain JS, no imports, like `public/share-cards.js`). `foldGame(events, rules)` → score by period, team fouls (per quarter, OT carries Q4), penalty, timeouts (2/3/1 per OT), player lines incl. `oreb`, foul-out/ejection flags, last-active players. `defaultFreeThrows`, `nextPos` (inserts between plays). Tests: `node --test test/score-engine.test.js`.
- `public/scorer.js` — the screen (module, loaded by `public/app.js` `initScorer` only when `[data-scorer]` is on the page). Saves every play to IndexedDB (`wknd-scorer`), sends batches to the API, retries; tap/hold buttons (`data-hold`), follow-up questions (assist, who lost it, free throws → shooter → made/missed), Undo = a `void` play.
- `views/app/score.js` — the shell (bundle JSON embedded: game, both rosters, rules, plays) and the "Score a game" list.
- `lib/scorer-publish.js` — `buildPublishPayload` turns plays into exactly what a wknd-stats import hands `importGameResults`, including the old `game_log_json` format (newest first, "[WHI 3 - BLA 0]" score tags, quarterEnd markers). Tests: `node --test test/scorer-publish.test.js` (checks `lib/game-detail.js` reads it).
- `lib/portal-db.js` — tables `score_games` (status setup → live → published, settings JSON: rules overrides, dnp, official), `score_scorers`, `score_events` (id from the phone, `INSERT OR IGNORE`, `pos` order, `payload_json`); `game_player_stats.oreb` (hidden on the site until next season).
- `server.js` — `// ── The scorer` block: `scoreAccess` (admins with games-stats, or listed scorers), `scoreBundle`, `GET /app/score`, `GET /app/score/:id`, `GET /admin/games/:id/score` (same screen on the site), `POST /api/score/:id/events` (validates type, team, roster), admin `POST /admin/games/:id/scoring` (on + scorers + waves), `/scoring/void`, `/scoring/dnp`, `/scoring/publish` (refuses a mismatch with the typed official score unless `anyway`). `afterGameImport` = the import's follow-up steps, shared with `POST /admin/games/:id/import`. `adminScoringPanel` + `describeScorePlay` feed `views/admin/game.js` `scoringTab`.
- Live score: `lib/live-score.js` `liveScoreData(bundle)` (score, period/break label, clock as of the last play, team fouls/penalty, timeouts left, box score lines, plays newest first; live pass only; tests `node --test test/live-score.test.js`). Rendered by `views/game.js` `liveParts` (site, upcoming branch of `gamePage`) and `views/app/feed.js` `appLiveParts` (app, `appGamePreviewPage` `live`). `server.js`: `liveArmed` (scoring on, not published, `settings.live_public !== false`), `liveScoreFor`, `liveChanged` (throttled 1 s, tells `/ws/games/:id/live`); `/games/:ref` and `/app/games/:id` answer `X-Live: 1` with the parts as JSON (`{on:false, waiting:true}` = armed, no plays yet). `public/live-score.js` (site script tag; app via `app.js` `initLive`) listens, swaps the parts, keeps the chosen team and open lists, flashes new plays, polls every 20 s without a socket; not live any more → reload (app: `window.wkndRefreshScreen`, never a reload, which would bring the phone's copy back). Admin switch: Scoring tab "Live score for everyone" (`live` on/off).
- Live score elsewhere: `server.js` `liveMini(game)` (score, `liveWhen` label, link) feeds the ticker (`views/ticker.js` `liveCell` / live chip; `liveChanged` clears `_tickerCache`), the homepage playoff scoreboard (`views/playoff-hero.js`, `next.live` replaces the countdown, "Follow it live") and Coming up's league card (`withLiveNextUp`, a copy so the AI summary never sees it).
- Scorer picked → `createNotification` type `scorer_assigned` (bell + push, always sent: `pushKindOf` gives '' = account message), link `/app/score/:id`; only newly added scorers, on `POST /admin/games/:id/scoring`.
- 4-point line: a court feature (`lib/court-page.js` COURT_FEATURES `four_point`, ticked in admin Papawis → Courts → a court; also shows on the court page). `hasFourPointLine(game)` → bundle `fourPoint`; the scorer drops the 4PT buttons when false. A game with no court keeps them.

- Review (2026-10-26, server.js "Review" block + views/admin/game.js `reviewSection`): checking the live plays or re-tracking from the video. One admin at a time: `settings.review` { by, name, playerId, kind, startedAt, at, ask }; `reviewGate` claims it on the first review action (final score, remove play, DNP, publish, video plays, opening the video scorer) and answers 423 to anyone else; `POST /admin/games/:id/scoring/review` start / finish / handover / ask / answer / take (super admin only). Bells: `review_started` to the other game admins (`gameAdminPlayers`: approved admins with the games section), `review_ask`, `review_handover`, `review_taken`. `reviewProgress`: final score · re-track % (video, by game time tracked) · who didn't play (`dnpSaved`) · publish; shown as a bar on the Scoring tab and under Status on /admin/games. - Steal / block (2026-10-26): a steal right after the other team's turnover replaces it (void + `stl { from }`), no question; a block right after their missed shot links to it (`ref`), no question; otherwise "Who lost it?" / "Whose shot?" (2PT/3PT; the answer inserts their missed shot just before the block). Tapping the other team's tile answers either. Clock: `whistle()` (foul, timeout, team technical/violation, refs) stops it and, if it was running, sets `ui.whistle`; the next live-ball play (`LIVE_BALL`: shot, reb, stl, blk; never FTs) restarts it with a note, and Start pulses meanwhile. Keeper phone only.
- Follow-ups (2026-10-26, Paolo's name for them): the optional questions after a play, `OPTIONAL` kinds `ast` (Assisted?), `lost`, `blocked`, `wentoff`, `andone`. They sit above the stat pad (the pad stays usable, and the next tap skips), with a quiet hairline border, "optional", an × and a thin bar that runs out (amber, turning red over the last couple of seconds: `scFollowTone`). They close on ×, a tap on empty space, or by themselves after `FOLLOW_MS` (8s; Bench / 2PT·3PT start it again). The bar uses a negative `animation-delay` so repaints don't restart it. Menus (`menu()`: team stats, foul/turnover kind, Fix, Fix the clock, game menu, side chooser) close the same ways (`CLOSABLE`) but have no timer, since the scorer opened them; there's no Cancel option, just ×. The DNP sheet has × too, with no outside tap, because it holds unsaved picks. The foul panel, the hand-over prompt and the first "Which side do you score?" stay open until answered.
- Team menu (2026-10-26): the team name opens labelled rows (`menu()` takes `{ group, items }`): Turnover (Team, Shot clock, 3s, 5s, 8s), Technical (Coach, Bench), Lineup (DNP…). The labels sit above the chips on a phone and beside them from 520px. The Sub button beside Timeout (`subMenu`) opens the Subs sheet (`ui.subs`, `subsSheet`). Tap court players to take them off (red, ↓) and bench players to put them on (green, ↑); picks pair up in the order tapped, and each tile shows its partner's number. "All 5" is a line change; a fouled-out or ejected player still on court starts marked. Save (`subSave`) makes one `sub` play per pair, and each player coming on takes the exact tile of the one they replace (`slots`).
- Gestures (2026-10-26): swipe a stat button up = FOUL/TO kinds (as a hold) or, on a made 2/3/4PT, the and-one (`andOne`: the basket, "who fouled?", then the foul panel set to 1 FT for the shooter; armed when no player is picked); swipe the last-play row left = Undo; swipe sideways in the Scoresheet (sheet or dock, not on the box score table) = next/previous tab; swipe the sheet down or tap above it = close; swipe a follow-up, a menu or the DNP sheet down = close (`swipeClose`). `paint()` waits while a swipe or slide is under way and keeps the sheet/dock scroll.
- Nothing overwrites (2026-10-26): plays are only ever added by id. POST events sets aside as pass 'late' (never refused, never counted) plays that could double up: the game is published, or tapped (`at`) after the final score was saved (`settings.finalAt`, set by `/admin/games/:id/final`), or from a phone whose side was taken over and tapped after it was last heard from (`score-lanes` `lostFor`, cleared when it scores a side again). Admins get a `review_late` bell; the Scoring tab's Late plays card adds them (not once published) or leaves them out (`dropped`, kept on record) via `POST /scoring/late`. The phone marks them `late` and leaves them out of its own game, with a note. The phone keeps everything in IndexedDB, saved on every change and on leaving (visibilitychange/pagehide), the clock too (`running`, `savedAt`: a running clock has run while away); the service worker serves `/app/score/:id` offline.
- Scorer type (2026-10-26): `players.is_scorer` (admin player page → Settings → Scorer, `POST /admin/players/:id/scorer`). `scoreAccess` gives a Scorer any game with scoring on; `scorableGameIds` (Score a game list, Me To do, site profile tile) = picked games plus, for a Scorer, every unpublished scoring game today or later (or live). First time scoring is turned on for a game, every Scorer gets a `scorer_game_ready` bell. Scorers never review (admin routes) or re-track video. Per-game picks still work for one-offs.
- Take-over safeguards (2026-10-26): late plays are judged by when the server receives them, never the phone clock: after publish (everyone), after the final score was saved (scorers' phones; the reviewing admin's fixes still count), or from a phone whose side was taken over (`settings.lostDevices`, saved with the game so a restart can't forget; cleared when that phone scores a side again). A take-over bells the game admins (`scorer_takeover`). The lanes view sends `holders` (quiet phones too, with `quiet` ms): the side chooser shows Ask (active), a greyed "went quiet · take over in Ns", then Take over (quiet 2+ min, anyone); admins can still take a side now from the pill menu.
- More safeguards (2026-10-26): the scorer asks the browser to keep its storage (`navigator.storage.persist`). POST events also sets aside, play by play, a play for the other team from a phone holding one side (`laneOf`; free throws, fouls, missed shots and voids may name the other team) and plays tapped impossibly fast (6 within 2 s per phone, `scoreTapLog`). Publish: one at a time (`claimScorePublish`, status 'publishing'), a snapshot first (`score_publish_snapshots`), and `POST /scoring/unpublish` (Undo publish) restores the game row, box score and DNP from it and reopens scoring. The Publish card lists checks (play after foul-out, DNP with stats, more assists than baskets, quarters vs final score), never a block. Plays carry who sent them (`scoreEventsWithBy`): By column and Removed plays on the Scoring tab, "fixed by" in the scorer's Play-by-play. ⋯ → Send my plays saves every play on the phone as a file (share sheet on phones, else a download); the Scoring tab's Import a phone's plays puts it under Late plays (`POST /scoring/import`). Daily backups on production: data/backups/portal-YYYY-MM-DD.db, 14 kept (`dailyBackup`).

## Gotchas
- Nothing shows anywhere until an admin turns scoring on for a game; publishing goes through `importGameResults`, which makes the game public at once (same as an import).
- Minutes are not tracked (`min: ''` in the payload). DNP is only what the admin marks in the review.
- `/app/score/:id` and the two scripts are in the service worker (`isScreen`, `isShellAsset`) so the screen opens offline; the page's embedded plays are merged with the phone's copy on open, then `GET /api/score/:id/events` brings in anything newer.
- Live pages: the hero's React/Share buttons are bound once by the page script, so only the hero pieces marked `data-lv-swap` are swapped; the site box score uses its own `data-lv-box-btn` switch (the finished page's is bound per element).
- Who can score (2026-10-26): every approved admin, whatever their admin sections (`isGameAdminPlayer`, read from the account, not the sign-in). Admins with the games section score as `admin`; the others score as `scorer` (no review powers: their plays after the final score are set aside, and no instant take-over). Reviewing and publishing still need the games section. Admins get the "games to score" to-do on Me, like Scorers (`scorableGameIds`).
- Two scorers at most (2026-10-26): `scoreLanes.scoring(id)` lists the phones holding a side and heard from within `STALE_MS`. With two others in, the Score list shows the game greyed out ("2 scorers already in: A and B"), and the scorer screen says so, with the sides greyed out and no Both (`twoIn()`). One phone going quiet for 2 minutes opens Take over. The server already refuses a third claim (conflict).
- Audit fixes (Fable + Claude audits, 2026-10-26):
  - **Taps:** after a hold or swipe, the click that follows the finger lifting is ignored (`swallowNext`), whatever the hold's length; the next touch clears it, so fast taps count.
  - **Follow-ups:**
    - Phones (<600px): one compact row floating above the last play, over the bench. Tablet landscape: the top of the Scoresheet column. Nothing moves when one comes or goes.
    - A tap on one of a follow-up's players on the court answers it (`followOpts`).
    - They queue (`ui.queue`): a bench player's play asks "Who went off?" first, then Assisted?/Who lost it?. Behind the foul panel they wait for the free throws.
    - A foul-out asks "Who comes on?" (`foulout`, no timer).
  - **Foul panel:**
    - × to close.
    - With no free throws, the next tap carries on.
    - With free throws owed, a tap on the shooting team picks the shooter; other taps wait, with a tip.
    - The shooter is pre-picked only for a shooting foul.
    - A shooting foul on a missed 3 defaults to 3 FTs.
    - A coach/bench technical (team menu) opens a 1-FT panel for any player of the other team.
  - **Engine:**
    - `team_tech` is no longer a team foul (FIBA).
    - A player technical doesn't put a bench player on court.
    - `period_end { final }` ends the game (`G.final`, board says FINAL).
  - **Undo:**
    - Subs saved together share a `batch` and undo together.
    - A play that replaced another (`restores`: steal after their turnover, Who lost it?) brings the replaced play back.
    - The Undone row keeps an Undo for the play before (two in a row).
  - **Clock:**
    - Runs on wall time (`runFrom`, `clockNow`) and catches up when the screen comes back.
    - Starts on the period's first live-ball play if nobody pressed Start.
    - At 0:00, Start becomes End.
    - End of Q4/OT with a winner offers "Game over" (OT only if tied or on purpose).
    - The clock phone stops on the other phone's whistles (`WHISTLES` via `pull()`) and restarts on its live-ball plays.
  - **Two scorers:**
    - The hand-over ask is a banner over the stat buttons; the tapped answer shows "Handing over…"/"Keeping it…" (`ui.handing`).
    - The asker sees a spinner, "Stop asking", and an "Asking X…" pill.
    - When the other scorer leaves (Back releases the side at once via `release()`, also on pagehide) or goes quiet 2 min, the remaining one gets "X left. Nobody is scoring Y" with "Score both teams" (`ui.alone`).
    - "Ask X for both teams" is never offered.
    - Lanes check-ins repaint only when something changed.
  - **Server:** the fast-tap rule counts taps, not plays (stat plays only; plays within 150 ms are one tap). `#0` sorts as a number.
  - **Layout:**
    - Team fouls past 5 show the count beside the red pips.
    - The Scoresheet button always shows (in ⋯ on short phones ≤700px tall, where tiles and buttons shrink so both fives fit).
    - Tablet landscape: court and bench never overlap. Tablet portrait: tiles grow into the spare height.
  - **Standards:** an in-app leave question (no `window.confirm`), the fail screen's inline styles moved to classes, `85dvh`, the miss icon is an SVG. The failure screen's pill says "Not loaded".
- Two-scorer alerts (mockup B, Paolo 2026-10-26, canvas claude.ai/artifact/1Kcrnp5Yqzza7oAVhDUa2T): an amber bar at the top (`alertBar()`, `.sc-alert`; centred, 420px, on tablets).
  - **Someone asks for this phone's side:**
    - A ring round their initials (`ini`, sent with the lanes) counts down `ASK_MS` (20 s), then the phone says no for you (`answer … timeout`; the asker reads "X didn't answer. Ask again?").
    - Buttons: "No, I'll keep BLUE" / "Let Joel score BLUE". The tapped one shows "Saying no…"/"Handing over…" until the server has it.
  - **The other scorer left or went quiet:** "Joel left the game · Nobody is scoring BLUE now", with "Score BLUE too (both teams)" and ×. Closed, the side pill keeps an amber dot (`ui.sideOpen`) until someone scores that side.
  - **Chimes (`chime()`):** Web Audio, no file. Two notes up for an ask (again after 10 s), two notes down when the other scorer leaves, one soft note on the asker's phone when the answer comes. Android also vibrates; iPhones can't, and their silent switch mutes it.
  - **⋯ → Sounds on/off:** `wknd-sc-sound` on this phone.
- Reviewing a game played without the scorer (2026-10-26): a game with a final score and scoring never turned on shows a Review card on its Scoring tab instead of "Turn on scoring": Re-track from the video (primary when it has a YouTube link) or Enter the plays. Starting it (`/scoring/review` start) switches scoring on quietly: `reviewOnly` (no live score, not in Scorers' games or to-do), `startedBell` (no game-started bell), `finalAt` (a scorer's phone can't add plays), no "ready for scoring" bells; only the usual "X is reviewing" bell to the other games admins. The final score stays the result at publish.
- Live game extras (phase 7, pulled forward 2026-10-26; mockup claude.ai/artifact/UfcErs6BJnQcZjXTTitbGH, Paolo "I like all"):
  - **Where:** five blocks above the live box score on the site's game page and the app's game screen, one markup (`views/live-extras.js`, `.lx-*` styled in both `styles.css` and `app.css`), swapped in with the live body as plays arrive.
  - **Win odds:** the Who wins? pre-game odds (frozen copy, none when odds are off/hidden) moved by lead and time left (`winChance`, normal model, SIGMA 13 points), with a line over the game.

  - **Team pace:** projected against each team's season usual, from Q2.
  - **Picks:** once picks close: % sweating, the split, faces, "You picked…".
  - **Plumbing:** maths in `lib/live-extras.js` (pure, `test/live-extras.test.js`); `server.js liveExtrasFor` caches the history per change of plays. Time-based numbers use the scorer's clock (marked "about"). Setting `live_extras_enabled` ('0' turns them off; no admin switch yet).
