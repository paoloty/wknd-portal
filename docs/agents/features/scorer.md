# Scorer (replaces wknd-stats live tracking)

Phase 1 (2026-10-25): one device scores a league game (both teams, lineups off), offline-first; an admin publishes it from the game's Scoring tab. Live score for everyone (site + app) added 2026-10-25. Later phases (video re-track, two scorers, lineups mode, Papawis) are planned, not built. Product decisions live in the scorer memory notes; mockups: claude.ai/artifact/6HBcExzSGjoQSzvjpkMPJQ.

## Files
- `public/score-engine.js` — the rules and maths, shared by the phone and the server (plain JS, no imports, like `public/share-cards.js`). `foldGame(events, rules)` → score by period, team fouls (per quarter, OT carries Q4), penalty, timeouts (2/3/1 per OT), player lines incl. `oreb`, foul-out/ejection flags, last-active players. `defaultFreeThrows`, `nextPos` (inserts between plays). Tests: `node --test test/score-engine.test.js`.
- `public/scorer.js` — the screen (module, loaded by `public/app.js` `initScorer` only when `[data-scorer]` is on the page). Saves every play to IndexedDB (`wknd-scorer`), sends batches to the API, retries; tap/hold buttons (`data-hold`), follow-up questions (assist, who lost it, free throws → shooter → made/missed), Undo = a `void` play.
- `views/app/score.js` — the shell (bundle JSON embedded: game, both rosters, rules, plays) and the "Score a game" list.
- `lib/scorer-publish.js` — `buildPublishPayload` turns plays into exactly what a wknd-stats import hands `importGameResults`, including the old `game_log_json` format (newest first, "[WHI 3 - BLA 0]" score tags, quarterEnd markers). Tests: `node --test test/scorer-publish.test.js` (checks `lib/game-detail.js` reads it).
- `lib/portal-db.js` — tables `score_games` (status setup → live → published, settings JSON: rules overrides, dnp, official), `score_scorers`, `score_events` (id from the phone, `INSERT OR IGNORE`, `pos` order, `payload_json`); `game_player_stats.oreb` (hidden on the site until next season).
- `server.js` — `// ── The scorer` block: `scoreAccess` (admins with games-stats, or listed scorers), `scoreBundle`, `GET /app/score`, `GET /app/score/:id`, `GET /admin/games/:id/score` (same screen on the site), `POST /api/score/:id/events` (validates type, team, roster), admin `POST /admin/games/:id/scoring` (on + scorers + waves), `/scoring/void`, `/scoring/dnp`, `/scoring/publish` (refuses a mismatch with the typed official score unless `anyway`). `afterGameImport` = the import's follow-up steps, shared with `POST /admin/games/:id/import`. `adminScoringPanel` + `describeScorePlay` feed `views/admin/game.js` `scoringTab`.
- Live score: `lib/live-score.js` `liveScoreData(bundle)` (score, period/break label, clock as of the last play, team fouls/penalty, timeouts left, box score lines, plays newest first; live pass only; tests `node --test test/live-score.test.js`). Rendered by `views/game.js` `liveParts` (site, upcoming branch of `gamePage`) and `views/app/feed.js` `appLiveParts` (app, `appGamePreviewPage` `live`). `server.js`: `liveArmed` (scoring on, not published, `settings.live_public !== false`), `liveScoreFor`, `liveChanged` (throttled 1 s, tells `/ws/games/:id/live`); `/games/:ref` and `/app/games/:id` answer `X-Live: 1` with the parts as JSON (`{on:false, waiting:true}` = armed, no plays yet). `public/live-score.js` (site script tag; app via `app.js` `initLive`) listens, swaps the parts, keeps the chosen team and open lists, flashes new plays, polls every 20 s without a socket; not live any more → reload (app: `window.wkndRefreshScreen`, never a reload, which would bring the phone's copy back). Admin switch: Scoring tab "Live score for everyone" (`live` on/off).
- Live score elsewhere: `server.js` `liveMini(game)` (score, `liveWhen` label, link) feeds the ticker (`views/ticker.js` `liveCell` / live chip; `liveChanged` clears `_tickerCache`), the homepage playoff scoreboard (`views/playoff-hero.js`, `next.live` replaces the countdown, "Follow it live") and Coming up's league card (`withLiveNextUp`, a copy so the AI summary never sees it).
- Scorer picked → `createNotification` type `scorer_assigned` (bell + push, always sent: `pushKindOf` gives '' = account message), link `/app/score/:id`; only newly added scorers, on `POST /admin/games/:id/scoring`.
- 4-point line: a court feature (`lib/court-page.js` COURT_FEATURES `four_point`, ticked in admin Papawis → Courts → a court; also shows on the court page). `hasFourPointLine(game)` → bundle `fourPoint`; the scorer drops the 4PT buttons when false. A game with no court keeps them.
- Phase 2 (branch scorer-phase2): corrections and the video pass. Engine: `dnp` plays (`{ on }`, cleared by the player's first stat; `foldGame().dnp`), `correction(events, target, fields, ids)` = void + the fixed play at the same spot (`fixes` = old id). Scorer: Fix on every log row (who / what stat / add a missed play after this = insert cursor `ui.after` / remove), All plays sheet, DNP per team, tap the clock to nudge it, `?pass=video` (admins; IndexedDB key `<game>:video`, optional embedded YouTube kept outside the repainting root). Server: `scorePass(req)` on bundle, events GET/POST, void, publish (`settings.publishedPass`); video plays never call `liveChanged`. Publish DNP = admin list ∪ scorer DNP marks (`lib/scorer-publish.js`). Admin Scoring tab: Video re-track panel, Live vs video (players whose lines differ), Publish picks the track (video by default once it has plays).
- Phase 3 (branch scorer-phase3): two scorers. `lib/score-lanes.js` (in memory; tests `test/score-lanes.test.js`): lanes 'a' | 'b' | 'both' | null, claim / ask / answer / ping, take over a phone quiet for 2 min (admins any time), clock keeper = Both else team A. `POST /api/score/:id/lanes` (every 4 s from each phone, carries its lane and, for the keeper, the clock; answers with `now` so the other phone runs the keeper's clock). Scorer: side chooser, hand-over prompt, the other side folded, "You: White · Ana: Blue · clock: Ana" bar, other phone's plays pulled on each check-in and on the live socket, Undo = this phone's own last play (`dev` on each play), Fix on any. Live pass only.
- Site entry points: `GET /score/:id` (the scorer at a site address, for site sign-ins; only `/app/score` works offline), `scoreHrefFor(req, gameId)` picks the app address when the viewer can use the app. Site game page strip `.gd-scorer` (views/game.js, upcoming/live), Me dashboard Today tile "Game to score" (views/player.js prfToday, `scoreGames`). The scorer_assigned notification links `/score/:id`; `appLinkFor` maps it to `/app/score/:id` in the app.
- `GET /api/score/:id/events` — the scorer screen pulls plays it doesn't have on open and when back online (admin removals, other phones).
- Entry points: Me's To do ("1 game to score"), the upcoming game screen's Start scoring (`appGamePreviewPage` `scoreHref`), the admin game page's Scoring tab.

## Gotchas
- Nothing shows anywhere until an admin turns scoring on for a game; publishing goes through `importGameResults`, which makes the game public at once (same as an import).
- Minutes are not tracked (`min: ''` in the payload). DNP is only what the admin marks in the review.
- `/app/score/:id` and the two scripts are in the service worker (`isScreen`, `isShellAsset`) so the screen opens offline; the page's embedded plays are merged with the phone's copy on open, then `GET /api/score/:id/events` brings in anything newer.
- Live pages: the hero's React/Share buttons are bound once by the page script, so only the hero pieces marked `data-lv-swap` are swapped; the site box score uses its own `data-lv-box-btn` switch (the finished page's is bound per element).
